# تدقيق تكرار طلبات GET لصفحة دخول الإدارة

**تاريخ الفحص:** 2026-10-23  
**البيئة:** Next.js 16.4.2 / App Router / development على `localhost:3000`، MySQL متاح.

## الخلاصة

لم يمكن إعادة إنتاج تحديث تلقائي أو حلقة إعادة توجيه من `/admin/login` في الاختبار المنضبط. فتح الصفحة مرة واحدة نتج عنه تحميل مستند واحد، وإعادة تحميل يدوية واحدة نتج عنها طلب مستند واحد، ولم تسجل أدوات المتصفح موارد جديدة خلال 10 ثوانٍ من السكون. لا توجد `useEffect` أو مؤقتات أو polling أو Middleware في صفحة الدخول.

السجلات التي تحتوي عدة أسطر `GET /admin/login 200` لا تكفي وحدها لتحديد من أرسل كل طلب، لأنها لا تحتوي معرّف تبويب أو عميل أو سبب التنقل. في جلسة الفحص ظهرت طلبات إضافية عند فتح الصفحة وإعادة تحميلها يدويًا، وعند فحص مسار إداري محمي أعاد التوجيه إلى صفحة الدخول. لذلك السبب المرجح هو تعدد عمليات فتح/إعادة تحميل أو طلبات اختبار متتابعة، وليس حلقة داخل صفحة الدخول. لم يُعطل Strict Mode أو HMR أو الحماية.

**لم يُجر أي تعديل على كود التطبيق** لعدم ثبوت خلل تكرار آلي. لا يمكن تقديم مقارنة قبل/بعد إصلاح مصدره غير مثبت؛ يسجل التقرير أعداد القياس المنضبط بدل الادعاء بتحسن غير واقع.

## القياس المنضبط لصفحة الدخول

| العملية | عدد طلبات مستند الصفحة | ملاحظات |
|---|---:|---|
| فتح `/admin/login` مرة واحدة | 1 | استجابة `200`. |
| إعادة تحميل يدوية مرة واحدة | 1 | سطر واحد جديد في سجل الخادم: `GET /admin/login 200 in 454ms`. |
| انتظار 10 ثوانٍ دون تفاعل بعد إعادة التحميل | 0 طلبات/موارد إضافية في القياس | بقي عدد موارد الصفحة كما هو؛ لم يظهر طلب تنقل أو API تلقائي. |
| إرسال اعتماد غير صحيح مرة واحدة | 0 طلبات مستند `/admin/login` إضافية | `GET /api/auth/providers` مرة (`200`)، `GET /api/auth/csrf` مرة (`200`)، و`POST /api/auth/callback/credentials` مرة (`401`). بقيت الواجهة على صفحة الدخول وعرضت رسالة خطأ. |
| فتح `/admin` دون جلسة | طلب واحد للمسار ثم انتقال واحد | `/admin` أعاد `307`، ثم `/admin/login` أعاد `200`؛ لا تكرار أو حلقة تحويل في ذلك المسار. |

أظهر سجل التطوير لطلبات صفحة الدخول المنفذة تباعًا أزمنة مختلفة، منها 929ms عند التهيئة الأولى ثم 184–462ms لطلبات المتصفح اللاحقة. هذه عينات تطوير متأثرة بالتهيئة وTurbopack، وليست قياس أداء إنتاج أو دليلًا على polling. ظهر كذلك سطر ضغط filesystem cache ورسائل Electron في مشغل التطوير؛ لا يفسر أي منهما طلب صفحة متكررًا بحد ذاته.

## المصادقة وإعادة التوجيه

- لم يوجد `src/middleware.ts` أو middleware يعيد كتابة `/admin/login`.
- صفحة `src/app/admin/login/page.tsx` لا تستخدم `useEffect` أو `router.refresh/push/replace` أو مؤقتًا. لا تُنفذ `window.location.assign` إلا بعد نجاح تسجيل الدخول.
- حماية `/admin` وباقي تخطيط الإدارة في `src/lib/auth/require-admin.ts`؛ غياب البريد من الجلسة يعيد توجيه المستخدم إلى `/admin/login`. صفحة الدخول خارج التخطيط المحمي، لذا لا تعيد توجيه نفسها.
- المستخدم ذو جلسة صالحة يستطيع عرض صفحة الدخول؛ لم توجد قاعدة تحويل من صفحة الدخول للمستخدم المسجل. لم تُختبر حالة تسجيل دخول ناجح أو انتهاء جلسة فعلية في هذه الجولة، لعدم استخدام بيانات اعتماد مسؤول؛ لا تُعرض كلمات مرور هنا.
- طلب بيانات اعتماد غير صحيحة لم ينقل المستخدم ولم ينشئ حلقة؛ أعاد NextAuth `401` للنموذج وعرض رسالة الرفض.
- App Router في Next.js المثبت يستخدم React Strict Mode افتراضيًا. وفق الدليل المحلي لـNext.js، Strict Mode مفعّل افتراضيًا في App Router منذ 13.5.1. لا يعطّل هذا طلب مستند HTTP كل بضع ثوانٍ؛ وصفحة الدخول لا تحتوي تأثيرات قد تعيد الجلب. لم يُغير الإعداد.

## جرد مصادر GET وطلبات البيانات

### المتصفح والواجهة

| الطلب/المصدر | الملف/الصفحة | التكرار والضرورة |
|---|---|---|
| تحميل المستند `GET /admin/login` | `src/app/admin/login/page.tsx` | مرة لكل فتح/إعادة تحميل مقصودة؛ لا طلب تلقائي في اختبار السكون. |
| `/api/auth/providers` ثم `/api/auth/csrf` | NextAuth Credentials عند إرسال نموذج الدخول من `src/app/admin/login/page.tsx` | ظهر كل منهما مرة في محاولة الدخول التي اختُبرت؛ طلبان تمهيديان متوقعان للمصادقة. |
| `POST /api/auth/callback/credentials` | NextAuth Credentials | طلب واحد لكل إرسال؛ حالة الاختبار الخاطئ `401`. |
| `GET /api/v1/cart` | `src/components/storefront/cart-provider.tsx` في أثر `useEffect([locale])` | جلب واحد عند تهيئة مزود السلة لكل تحميل/لغة؛ مطلوب لمزامنة سلة الضيف. لا يعمل في `/admin/login`. |
| طلبات سلة أخرى | `cart-provider.tsx` | `/api/v1/cart/items` عند ترحيل عناصر قديمة أو الإضافة، وPATCH/DELETE عند تعديل المستخدم؛ إجراءات صريحة وليست polling. |
| `/api/admin/v1/*` | نماذج/مكونات لوحة الإدارة | `fetch` الحالية للكتابة تستخدم POST/PATCH/DELETE؛ القراءة في صفحات Server Components تتم مباشرة من Prisma ولا يوجد polling عميل. |
| خطوط وأصول `/_next/static/*` | Next.js/المتصفح | موارد ثابتة تُحمّل عند فتح المستند؛ لا تُعد طلبًا متكررًا للمسار. |
| قناة HMR في التطوير | عميل Next.js/Turbopack | قناة أدوات تطوير منفصلة؛ لا تظهر كإعادة GET للمستند خلال السكون المقاس. |

بحث المصدر عن `window.location.reload`, `setInterval`, `setTimeout`, `router.refresh/push/replace`, SWR/React Query وAxios لم يجد إعادة تحميل أو polling عام. الاستخدامات الموجودة: `router.refresh()` بعد عمليات كتابة إدارية ناجحة، مؤقت إخفاء رسالة السلة، و`useEffect` محلي لتفاعل دليل المقاسات/تهيئة السلة/تنظيف سلة ناجحة؛ لا ينطبق أي منها على صفحة دخول الإدارة.

### صفحات GET

الصفحات الديناميكية التالية قِيست بطلب HTTP مستقل واحد لكل مسار؛ لا يعني هذا أنها جميعًا استعلام API من المتصفح، إذ إن Server Components تقرأ Prisma على الخادم:

| المسارات المقاسة | الاستجابة |
|---|---|
| `/ar`, `/en`, `/ar/products`, `/en/products`, `/ar/search?q=not-found-audit`, `/ar/cart`, `/ar/checkout`, `/ar/account`, `/ar/orders`, `/ar/wishlist`, `/ar/about`, `/ar/contact`, `/ar/shipping`, `/ar/returns` | `200` |
| `/admin/login` | `200` |
| `/admin` دون جلسة | `307` ثم صفحة الدخول `200` |
| مسار منتج غير موجود عبر API | `404` متوقع |
| صفحة محتوى غير موجودة عبر API | `404` متوقع |

## نتائج واختبارات

- فتح `/admin/login`: `200`.
- انتظار 10 ثوانٍ دون تفاعل: 0 مورد إضافي بالمتصفح.
- إعادة تحميل يدوية واحدة: GET مستند واحد، 200.
- اعتماد خاطئ: providers GET واحد، csrf GET واحد، callback POST واحد `401` ورسالة خطأ؛ لا إعادة توجيه.
- غير مسجل: `/admin` يعيد `307` إلى تسجيل الدخول؛ API إدارة يعيد `401`.
- تسجيل الدخول الصحيح/انتهاء جلسة: غير منفذ في هذه الجولة؛ يحتاج اعتمادًا/جلسة اختبار صالحة.
- `npm.cmd run lint`: ناجح.
- `npm.cmd run typecheck`: ناجح.
- `npm.cmd test`: 16/16 ناجحة، بينها اختبار تكامل MySQL للصحة والـcheckout.
- بناء الإنتاج: لم يُعد تشغيله؛ لم تتغير ملفات التطبيق.

## القرار والإجراء

لا يوجد خلل مثبت يستدعي تعديلًا أو تعطيلًا. للمقارنة على جهاز المستخدم: افتح تبويبًا واحدًا لصفحة الدخول، صفّر Network، سجّل الطلبات لمدة 10 ثوانٍ دون تفاعل، ثم نفّذ Reload يدويًا مرة واحدة. افحص أعمدة Initiator وType؛ طلب `document` واحد عند الفتح/Reload طبيعي، وموارد HMR/static منفصلة. إذا تكرر `document` دون تفاعل، أرسل توقيت الطلبات وعمود Initiator وعدد التبويبات؛ عندها يمكن تتبع مصدر العميل المحدد. لا ترسل Cookie أو CSRF token أو بيانات اعتماد.
